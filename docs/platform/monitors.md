# Monitor behavior

Dated sections are investigations, oldest first. A later one can supersede an earlier one.

## Rules and fields

| Fact | Tag |
|---|---|
| `hl.monitor({ output, mode, position, scale, transform, mirror, disabled, … })`. `mode` accepts `"WxH@R"`, `"preferred"`, `"highres"`, `"highrr"`, `"maxwidth"`. `output` may be a name or `desc:<description>`; an empty output defines a fallback rule. | [DOC] |
| Position is a virtual layout in an inverse-Y system; negative values are allowed (`-1920x0` is left, `0x-1080` is above). | [DOC] |
| `hyprctl monitors all -j` lists enabled and disabled monitors. Fields used: `name`, `description` (e.g. `<make> <model> <serial>`), `make`, `model`, `serial`, `transform`, `disabled`, `mirrorOf` (`"none"` or the numeric id as a string, e.g. `"0"`), `availableModes`, geometry. The laptop panel has an **empty serial**; its identity falls back to model + connector. | [LIVE] |
| `availableModes` contains duplicates and near-duplicates (e.g. `1920x1080@60.00Hz`, `1920x1200@59.88Hz`). `hl.monitor` **accepted the exact reported spelling** `1920x1080@60.00Hz` with no config error and preserved the refresh. Deduplicate for display only; keep one exact allowlisted string per choice. | [LIVE] |
| `mirror = "<output>"` works. **Re-enabling a monitor without a mirror field keeps its previous mirror rule**; send `mirror = ""` to clear it. Always send explicit `disabled` and `mirror` fields. | [LIVE] |
| In Mirror mode Hyprland reports the sink at the source output's runtime `x,y` even though Station's marked monitor rule retains the sink's independent Extend geometry. Rebuilding the editor draft from `hyprctl monitors all` therefore overlaps the cards. Parse only Station's strict generated block and use its validated geometry for the draft; compositor snapshots remain authoritative for runtime state. | [LIVE][SRC] |
| `disabled = true` and `disabled = false` work at runtime. | [LIVE] |
| **`hyprctl reload` resets runtime monitor changes** (disabled and mirror return to what the config says). Therefore mode state must be re-applied after every `configreloaded`. | [LIVE] |
| **Precedence: with two rules for the same output, the last one wins**, both inside one runtime eval and when a marked block is appended at the end of `monitors.lua`. | [LIVE] |
| Software disable of a monitor: workspaces and windows migrate to the survivor first, **then** `monitorremoved` fires. | [LIVE] |
| Station v1 used `dpms off` for single mode; v2 uses `disabled = true`. | [SRC] |

## Switching and crashes

| Fact | Tag |
|---|---|
| On 2026-10-08, while switching Station Extend/Mirror/Single, Qt clients (including Omarchy shell) twice logged `There are no outputs - creating placeholder screen` (00:05:51 and 00:06:30 local). At 00:06:43 the shell crashed with SIGSEGV in `QtWaylandClient::QWaylandWindow::setGeometry` during xdg-toplevel configure. This is the same stack and zero-output signature as [Quickshell issue #1133](https://github.com/quickshell-mirror/quickshell/issues/1133). The local core confirms one crash; the earlier zero-output episodes are not themselves proof of two more crashes. | [LIVE] |
| Before the repair, Station's runtime Single rules followed connector enumeration, so switching the sole active output from `eDP-1` to `HDMI-A-2` could disable `eDP-1` before enabling `HDMI-A-2`. Mirror rules could likewise mirror a live output to a source not yet enabled. The preview also sent geometry rules for every monitor on a mode-only edit. These are plausible sources of the observed zero-output transition, although the core does not identify which `hl.monitor` call preceded it. The repaired rule order enables the Single destination or Mirror source first and disables outputs last; mode-only previews omit geometry rules. | [SRC][INFER] |
| During repeated previews, the expected monitor-event list was calculated from the original preview snapshot, not the most recently applied preview. A second mode change could therefore classify its own `monitoradded`/`monitorremoved` as external hotplug and cause a reload while previewing. The repair compares each mode preview with the last applied mode state. | [SRC] |
| The file supplied after the 2026-10-08 Single-HDMI crash, `hyprlandCrashReport1032.txt`, was a byte-for-byte copy of a cached 2026-09-10 report and showed an older renderer failure. The report generated by the reported action was `hyprlandCrashReport1041.txt` at 05:42:03. It records SIGSEGV in `CInputManager::refocusLastWindow` from `CLayerSurface::onUnmap`/`onDestroy`, immediately after Aquamarine disabled `eDP-1`. The user journal at 05:42:02 also records Quickshell creating a placeholder because it temporarily saw no outputs, followed by four layer-shell screen warnings and the Hyprland crash. This is not an OOM: 11 GiB was available and swap use was zero. | [LIVE] |
| The Station popup is an Omarchy `Ui.KeyboardPanel`: while open it is a full-screen overlay layer surface with a Hyprland focus grab, plus non-focused dismissal layer surfaces on the other outputs. Removing the output that owns the open popup lets Hyprland destroy that focused layer during monitor teardown—the exact path in report 1041. Station now treats output removal as a handshake: the owning widget suppresses its 140 ms fade, closes, waits 180 ms for Wayland commits, and acknowledges; the service then enables the destination if necessary, focuses it, applies the disabling/mirroring rule, and only after compositor success publishes the new panel owner. Revert uses the same sequence before a saved Single/Mirror reload. A 1.2 s missing-ack timeout fails closed instead of removing the output. The exact `eDP-1 panel → Single HDMI-A-2` ordering and reverse-Single rollback are covered by the transaction double; physical confirmation under the repaired code is still pending. | [SRC][QTTEST] |
| A separate core at 05:41:13 was `/opt/zen-browser-bin/zen-bin`, not Zed. It failed in its GTK/Wayland event path about 46 seconds before the Hyprland crash. Obsidian's Electron process had a similar GTK/Wayland SIGSEGV at 05:35. Neither stack contains Station or Hyprland monitor code, so the available evidence does not establish that Station caused those earlier client crashes. | [LIVE] |

## Ten-bit outputs (2026-11-21)

- **[SRC]** `hl.monitor` takes `bitdepth` (`/usr/share/hypr/stubs/hl.meta.lua`), and
  Omarchy's example is `bitdepth = 10`. `hyprctl monitors -j` reports the result as
  `currentFormat`: `XRGB8888` at 8 bits, a `…2101010` format at 10.
- **[LIVE]** `Hyprland --verify-config -c` on Hyprland 0.57.2 answers `config ok` for
  Station's Extend, Mirror and Single blocks with `bitdepth = 10`. It rejects an unknown
  field (`hl.monitor: unknown field 'bitdepthx'`), so the check reads the field. It
  starts no compositor and changes no output.
- **[INFER]** The maintainer has no 10-bit monitor. Whether a real output stays at 10
  bits through a Keep and a reload is unverified. GitHub issue #14 reported the drop.
