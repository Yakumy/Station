# Color Match ICC behavior

## Color Match ICC profiles (2026-11-11)

Hyprland 0.56.2, i915, `HDMI-A-2` and `eDP-1`. Profiles were generated by Station's
own `ColorMatch.js` (an early test used an equivalent Python generator), checked with
lcms2, and judged on screen by the maintainer.

- [SRC] Hyprland links `liblcms2`, parses `icc = "/absolute/path"` in `hl.monitor`,
  builds a 3D LUT from it (`iccLut3D`) and has `updateVCGTRamps`. `render:icc_vcgt_enabled`
  is true by default. `hyprctl monitors` still reports `colorManagementPreset: srgb` with
  a profile applied, so it cannot confirm one.
- [LIVE] A profile with sRGB colorants and a `vcgt` tag (red 1.0, green 0.55, blue 0.2)
  had no visible effect, after a reload and after a live `hyprctl eval`. `modetest -M i915`
  showed the CRTC's `GAMMA_LUT` empty. Do not rely on `vcgt`.
- [LIVE] The same tint written into the colorants (each scaled by 1/gain) turned the
  screen visibly orange. lcms predicted white as (255, 196, 124).
- [LIVE] `hyprctl eval 'hl.monitor({ output = "HDMI-A-2", icc = "/path" })'` applies a
  profile immediately, with no reload, and leaves mode, position, scale and transform as
  they were. So a partial `hl.monitor` merges into the existing rule.
- [LIVE] `icc = ""` is rejected ("error applying field 'icc'"). A `hyprctl reload` whose
  configuration names no profile returns the monitor to its normal colors. A reset
  therefore needs one reload.
- [LIVE] Saturation 50% (luminance-preserving matrix in the colorants) on `HDMI-A-2` and
  gamma 1.40 (a shared 1024-entry `curv`) on `eDP-1` were both visible at once. lcms
  predicted red → (204, 92, 92) and mid-grey 128 → 96. A neutral profile is the identity
  in lcms.
- [LIVE] Editing `monitors.lua` with `sed -i` did not trigger an automatic reload here,
  although `misc:disable_autoreload` was false. Station's writes do not rely on it.
- [LIVE] `debug:disable_logs` is true under Omarchy, so Hyprland logs nothing about ICC
  parsing. A reload resets a runtime `disable_logs = false`.
- [LIVE] A saturation 0% profile (matrix floor 0.2%) was accepted by `hyprctl eval` with
  no config error; lcms (`transicc`) maps sRGB red, green and blue to grey within one
  code value. Not judged on screen by the maintainer yet.
- [LIVE] Saturation 200% and gamma 0.60 profiles were each accepted by `hyprctl eval` on
  `HDMI-A-2` with no config error, and a reload restored the monitors. lcms maps sRGB
  (200, 120, 60) to (243, 95, 0) at 200%, clipping at the gamut edge, and mid-grey 128 to
  169 at 0.60. Not judged on screen by the maintainer yet.
- [INFER] Screenshots should not show the correction, because it applies at scanout
  composition. Not checked.
